# ALIA — Analog Loop with Integrated Audit

Reference implementation and full experimental record for:

> M. Nawito, "Tier-Wise Recovery and Simulator-Audited Reasoning in an
> Un-Augmented LLM Analog Design Loop,"
> IEEE ICTA 2026 (submitted).

A frozen, un-augmented large language model designs a five-transistor OTA on the
open GF180MCU PDK by iterating against ngspice. Everything except the reasoning
turn is deterministic: a lint/repair layer at intermediate-representation level, a
netlist renderer, ngspice, a measurement stage and a specification evaluator. A
separate audit layer re-simulates, in isolation, the single causal claim the model
states behind each revision, and adjudicates it against the simulator.

## What is in this repository

```
alia/         the harness: IR, lint/repair, render, sim, measure, audit, runner
tools/        aggregation and transcript verification
fig/          figure generators (every figure in the paper is generated by script)
data/         the complete experimental record (see below)
```

`data/` contains:

| file | contents |
|---|---|
| `episodes.jsonl` | every harness event, one JSON object per line, each tagged `"phase": "pilot"` or `"phase": "phase3"` |
| `per_episode.csv` | one row per episode: arm, seeded flag, status, converging iteration, first-failure tier, parse errors, repair actions, audit verdicts, and the converged metric quadruple |
| `phase3_stats.json` | the aggregate the paper's tables and figures are drawn from. `audit.clean` is the split the paper reports (88 records, 20 of 20 clear verdicts); `audit.totals_all_episodes` additionally includes the fault-injected episodes and is not a published figure |

`per_episode.csv` exists so that every published number can be recomputed from the
release without re-running anything. `python3 tools/aggregate.py` regenerates
`phase3_stats.json` from the per-episode state files; the figure scripts in `fig/`
regenerate Figs. 1, 2, S1 and S2.

## Reproducing the environment

ngspice 42 or later and the open GF180MCU PDK (`gf180mcu_fd_pr` model library) are
required. `python3 alia/validate.py` checks the toolchain end to end against an
analytic RC reference and must agree to within 30 ppm before any episode is run.
`python3 alia/test_repair_audit.py` exercises the lint/repair rules and the audit
verdict logic.

## NOTES on the released record

These are the six places where a reader recomputing from `data/` will see something
that needs explaining. They are documented here rather than left to be discovered.

1. **Pilot rows are present and tagged.** Episodes `ep01` and `ep02` were run on
   30 July 2026 to validate the protocol before Phase 3 and are not part of any
   statistic in the paper. Filter on `phase == "phase3"` to reproduce the paper's
   227 ingested turns, 33 reply-contract failures and 194 parsable replies.
   Including the pilot gives 233 / 34 / 199.

2. **Four one-shot retry packets were built and never dispatched.** Episodes
   `ep_o01`, `ep_o07`, `ep_o10` and `ep_o17` failed the single-JSON reply contract at
   iteration 0. Under the status rule in force at that moment the runner queued an
   iteration-1 packet for each; the rule was then corrected so that a reply-contract
   failure consumes an iteration of budget, which makes those episodes terminal at
   K = 0, and the four packets were never sent. The log therefore contains four
   `packet` events with no matching `ingest`. No reasoner turn was discarded and no
   episode outcome changed.

3. **One packet-hash divergence, in the pilot only.** `ep02` iteration 2 has two
   `packet` events 43 s apart with different shas, because the episode trace grew
   between the two builds. Phase 3 contains 370 packet-rebuild events, all tagged
   `verified-identical` with matching shas and zero divergences.

4. **33 `ingest` rows carry no `model` field.** Those are exactly the turns whose reply
   failed the single-JSON reply contract; the field is written from the parsed reply. The
   pinned-model check runs against the **transcripts**, where all 227 turns carry the single
   model string, not against this log.

5. **The ablation arms were interrupted and resumed.** An external usage limit on the
   reasoner service interrupted the run on 31 July at one wall-clock instant, leaving
   8 of 20 −repair episodes, 14 of 20 −feedback episodes and the 5 seeded episodes run
   without repair in flight; the run resumed on 2 August and every episode reached a
   terminal state. Since each turn is stateless and every packet is rebuilt from disk
   and hash-verified on resumption (the log tags these rebuilds `verified-identical`),
   the interruption alters no episode's course. Timestamps in the log reflect the gap.

6. **Seeded episodes carry arm-dependent tier labels.** In `per_episode.csv` the five
   fault-injected episodes run with repair active (`ep_fs01–05`) are tiered **T1** while the five
   run with repair disabled (`ep_rs01–05`) are tiered **T3**, from the same injection: the tier is
   assigned after the repair layer has run, so with repair on the tier-3 faults are absorbed and
   the unknown-kind refusal is what surfaces. Filter on `seeded == 0` to reproduce the paper's
   tier counts; the paper's "T1 contributed nothing" is a statement about clean episodes.

## Protocol record

Each reasoning turn ran in a fresh, stateless context. The prompt is a pure function
of on-disk state, so the packet is by construction the whole episode state, and each
packet embeds a hash of its own body that the reply must echo. Per-turn transcripts
are released alongside this repository. Each transcript line carries `{type, timestamp, message}` with the message object verbatim (opaque provider attestation signatures on thinking blocks are removed; the thinking text as received — empty in every turn — is preserved); runtime metadata of the execution environment (session identifiers, host paths, tool-availability notices) is stripped and carries no experimental content. `tools/verify_transcripts.py` checks, for
every phase-3 turn, that the prompt the reasoner received is byte-identical to the packet on
disk, that the turn contains zero tool-use blocks, and that the model string is the
single pinned reasoner. Replies were extracted from the transcripts rather than
transcribed, so the transcript is the authoritative record.

## ICM 2026 extension: the two-stage OTA task

Reference record for:

> M. Nawito, "Fulfilling Competing Analog Design Constraints in an
> Un-Augmented LLM Design Loop," IEEE ICM 2026 (invited paper, to appear).

The harness above is unchanged. A task registry makes the task definition and its
frozen specification selectable per episode: `--task 5t` reproduces every behaviour
described above, and `--task twostage` selects the new task. The two-stage task
prescribes the classical two-stage Miller-compensated OTA on the same PDK with a
gain-dominated specification (DC gain >= 70 dB, GBW >= 3 MHz, phase margin >= 60
degrees, supply current <= 100 uA).

`data/twostage/` contains:

| file | contents |
|---|---|
| `episodes/` | all 30 campaign episodes (`epf01`-`epf15` closed loop, `epo01`-`epo15` one-shot) and the two pilot episodes (`eppilot01`/`eppilot02`, excluded from every published count): per-turn prompts, extracted replies, state files and simulation decks |
| `episodes.jsonl` | every harness event of the campaign, one JSON object per line |
| `campaign_summary.json` | the aggregate the paper's tables and figures are drawn from |
| `fixture_twostage.py` | the manually designed reference amplifier that confirmed feasibility through the identical evaluation path before any runs |

The per-turn prompts embed the same body hash that the reply must echo, so the
pairing of every recorded reply with its recorded prompt can be checked exactly as
for the 5T record.
